# Secrets And Host Keys

This repository assumes impermanence hosts keep private runtime identity under
`/persist/keys`. Nix does not copy or generate these files during activation:
set them up intentionally before switching to a configuration that depends on
them.

Public key metadata lives in `secrets/keys.nix`. Private keys and encrypted
SOPS payloads stay outside the Nix store.

## Runtime Layout

```text
/persist/keys/
  ssh/
    ssh_host_ed25519_key
    ssh_host_ed25519_key.pub
  sops/
    secrets.yaml
```

Create the directories before the first switch (as root):

```bash
install -d -m 0700 -o root -g root /persist/keys/ssh
install -d -m 0700 -o root -g root /persist/keys/sops
```

Run `./users/scripts/setup-sops.sh` before each switch (as root) to ensure keys, permissions,
and `/persist/keys/sops/secrets.yaml` are in the expected state.

## Host SSH Identity

If the host already has an SSH identity that clients trust, copy it. This keeps
the SSH host fingerprint stable:

```bash
install -m 0600 -o root -g root \
  /etc/ssh/ssh_host_ed25519_key \
  /persist/keys/ssh/ssh_host_ed25519_key

ssh-keygen -y -f /persist/keys/ssh/ssh_host_ed25519_key \
  | tee /persist/keys/ssh/ssh_host_ed25519_key.pub >/dev/null
chown root:root /persist/keys/ssh/ssh_host_ed25519_key.pub
chmod 0644 /persist/keys/ssh/ssh_host_ed25519_key.pub
```

For a fresh host with no identity to preserve, generate the key explicitly:

```bash
ssh-keygen -t ed25519 -N '' \
  -f /persist/keys/ssh/ssh_host_ed25519_key
```

## Register The Host

Derive the host's age recipient from its public SSH host key:

```bash
ssh-to-age -i /persist/keys/ssh/ssh_host_ed25519_key.pub
```

Then update:

- `secrets/keys.nix`: add the machine block printed by `setup-sops.sh` and add
  its hostname to `keyed`.
- `.sops.yaml`: regenerated by `./users/scripts/setup-sops.sh` from `secrets/keys.nix`.

Setting `nixBuild.useRemoteBuilders = true` authorizes the registered host as a
build-mesh client; `modules/distributed-builds.nix` reads its host key from this
registry.

SOPS decryption is strictly restricted to `root`. `secrets/sops.nix` sets
`SOPS_AGE_SSH_PRIVATE_KEY_FILE=/persist/keys/ssh/ssh_host_ed25519_key`, and
`./users/scripts/setup-sops.sh` also writes `/root/.config/sops/age/keys.txt`
from the host SSH private key.

## Install Encrypted Payloads

The repo copy `secrets/secrets.yaml` is the source of truth. On each switch,
`setup-sops.sh` refreshes `/persist/keys/sops/secrets.yaml` when the content
differs.

Do not place private keys in the repo. The repo keeps examples, Nix wiring, and
public key metadata only.

## Encrypted Payload Shape

Use `secrets/.secrets.example.yaml` as the schema reference. Current service
secrets use these shapes:

```yaml
cloudflare_api_token: |
    CLOUDFLARE_DNS_API_TOKEN=...
nix:
    # fine-grained PAT, Public Repositories (read-only), no permissions (rate-limit only)
    access-tokens: |
        access-tokens = github.com=<PAT>
keys:
    deploy: string
passwords:
    nextcloud: string
tokens:
    attic-server-jwt-env: |
        ATTIC_SERVER_TOKEN_RS256_SECRET_BASE64=<base64-rsa-key>
    attic-push-token: string
    cloudflared: string
    deepseek: string
    forgejo-runner: string
    github-runner-nixos: string
    localtonet-authtoken: string
    playit-agent: |
        SECRET_KEY=...
samba:
    credentials:
        yi: |
            username=...
            password=...
services:
    grafana:
        secret-key: string
    proton:
        wireguard_private_key: string

```

PostgreSQL on `yifuwuqi` uses local Unix socket peer authentication. It creates
service-matching roles and databases (`forgejo`, `atticd`, `grafana`), so there
are no PostgreSQL passwords to add to SOPS.

Keep app identity secrets stable across database resets:

- Attic JWT signing: `tokens/attic-server-jwt-env`
- Attic push token: `tokens/attic-push-token`
- Grafana encryption key: `services/grafana/secret-key`
- Forgejo generated runtime secrets:
  `/var/lib/forgejo/custom/conf/{secret_key,internal_token,oauth2_jwt_secret,lfs_jwt_secret}`

Database data can be dropped or recreated without rotating these secrets. Losing
database data may still require service bootstrap again: Forgejo admin/mirrors,
Attic cache/tokens, or non-declarative Grafana state.

> **Note on Forgejo Runners:** If you wipe the Forgejo database, you must also delete the runner's local state directory (`rm -rf /var/lib/forgejo-runner/yifuwuqi` as root) before restarting the runner, otherwise it will try to authenticate using its stale state and fail.

Recipes:

| SOPS key                      | Value format  | How to get it                                                                         |
| ----------------------------- | ------------- | ------------------------------------------------------------------------------------- |
| `tokens/attic-server-jwt-env` | env file      | Generate locally; command below                                                       |
| `tokens/attic-push-token`     | raw token     | Generate with `atticd-atticadm` after `atticd` starts; command below                  |
| `tokens/forgejo-runner`       | raw token     | Forgejo UI: Site Administration -> Actions -> Runners -> Create new runner            |
| `tokens/github-runner-nixos`  | raw token     | GitHub repo: Settings -> Actions -> Runners -> New self-hosted runner                 |
| `keys/deploy`                 | PEM string    | Generated via `./users/scripts/setup-sops.sh` (or `--rotate`) on any configured host  |
| `services/grafana/secret-key` | random string | Generate locally: `openssl rand -hex 32`. Keep stable; it encrypts Grafana DB secrets |

| `cloudflare_api_token` | env file | Cloudflare API token with DNS edit for the ACME zone, stored as `CLOUDFLARE_DNS_API_TOKEN=<token>` |
| `tokens/cloudflared` | raw token | Cloudflare Zero Trust -> Networks -> Tunnels -> create/select tunnel -> copy tunnel token |
| `tokens/playit-agent` | env file | playit.gg agent setup token, stored as the full env line expected by the container, e.g. `SECRET_KEY=...` |
| `tokens/localtonet-authtoken` | raw token | Localtonet dashboard auth token |
| `tokens/deepseek` | raw API key | DeepSeek console API key |
| `nix/access-tokens` | nix.conf fragment | Optional GitHub token for Nix flake fetches; see recipe below |
| `passwords/nextcloud` | plain password | Initial Nextcloud admin password; generate with `openssl rand -base64 24` or choose one |
| `proton/wireguard_private_key` | raw token | ProtonVPN Dashboard -> Downloads -> WireGuard -> generate & copy `PrivateKey` from `.conf` |
| `samba/credentials/yi` | credentials file | SMB account credentials: `username=...` and `password=...` |

Tokens generated by external UIs may expire if unused. If first deploy was long
after generation and a runner/tunnel fails registration, generate a fresh token
from the same UI and replace the SOPS value.

Nix GitHub access token (`nix/access-tokens`):

Raises the GitHub API quota for `github:` flake inputs (60/h unauthenticated →
5000/h authenticated). Opt-in per host: import `modules/nix-access-tokens.nix`
in the host configuration and set `services.nix-access-tokens.enable = true;`
(only `yifuwuqi` does this today). Nix then `!include`s
`/run/secrets/nix/access-tokens` (rendered from the SOPS value below). The key
must exist in that host's sops file — enabling the option without it makes
`sops-install-secrets` fail at activation. With the option off (the default),
neither the secret nor the `!include` is rendered and Nix runs unauthenticated.

Use the **least privilege** token that still authenticates:

1. Open [GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens](https://github.com/settings/personal-access-tokens/new).
1. Note: e.g. `nix-flake-fetches`. Expiration: your choice.
1. Repository access: **Public Repositories (read-only)**. Grant **no
   permissions** under Permissions — none are needed for public repo rate
   limits. Do not use a `gh` OAuth token (`gho_…`) or any token with
   repository/organization permissions.
1. Generate and copy the token once.

SOPS value must be a full `nix.conf` fragment (not the raw token alone):

```text
access-tokens = github.com=<PAT>
```

```bash
# as root (su -) in /home/yi/the.files/nixos; paste PAT when prompted; value is never printed
read -rs TOKEN
sops set secrets/secrets.yaml '["nix"]["access-tokens"]' \
  "\"access-tokens = github.com=${TOKEN}\""
unset TOKEN
```

Or edit with `sops secrets/secrets.yaml` (as root) and paste the line under `nix.access-tokens`.

### Attic Bootstrap (After Database Resets)

When resetting the database, the Attic caches are destroyed. You must manually recreate the admin token, cache, and push tokens before `attic-watch-store` or CI can push:

1. **Generate a new admin token (as root):**

   ```bash
   atticd-atticadm make-token --sub "*" --validity "10 years" \
     --pull "*" --push "*" --create-cache "*" --configure-cache "*" \
     --configure-cache-retention "*" --destroy-cache "*"
   ```

1. **Drop into a shell with the attic client:**

   ```bash
   nix shell github:zhaofengli/attic#attic
   ```

1. **Log in locally to the Attic server:**

   ```bash
   attic login yi http://127.0.0.1:24203 <admin-token-from-step-1>
   ```

1. **Recreate the cache:**

   ```bash
   attic cache create yi --public --priority 38
   ```

1. **Update the system's trusted public keys:**

   ```bash
   attic cache info yi
   ```

   Take the public key from the output and update `trusted-public-keys` in `modules/nix-settings.nix`.

1. **Generate the new push token** for SOPS (using the command in the table above).

## Rekey Safely

When `secrets/keys.nix` changes recipients, regenerate `.sops.yaml` first, then run
`sops updatekeys` against the encrypted files (it updates recipient metadata without
printing decrypted YAML), and finally sync to `/persist/keys/sops/secrets.yaml`:

```bash
su -
cd /home/yi/the.files/nixos

# 1. Regenerate .sops.yaml from secrets/keys.nix
./users/scripts/setup-sops.sh

# 2. Rekey secrets/secrets.yaml to match .sops.yaml
SOPS_AGE_SSH_PRIVATE_KEY_FILE=/persist/keys/ssh/ssh_host_ed25519_key \
  sops updatekeys -y secrets/secrets.yaml

# 3. Sync the rekeyed file to /persist/keys/sops/secrets.yaml
./users/scripts/setup-sops.sh
```

## Edit Secrets

Only `root` can decrypt or edit `secrets/secrets.yaml` (`yi` is not an age
recipient). `setup-sops.sh` derives `/root/.config/sops/age/keys.txt` from the
host SSH key (`/persist/keys/ssh/ssh_host_ed25519_key`), and
`SOPS_AGE_SSH_PRIVATE_KEY_FILE` is also set to `/persist/keys/ssh/ssh_host_ed25519_key`
so `sops` works as root even before `setup-sops.sh` has run:

```bash
su -
cd /home/yi/the.files/nixos
sops secrets/secrets.yaml
./users/scripts/setup-sops.sh
```

Always run `./users/scripts/setup-sops.sh` after editing `secrets/secrets.yaml`
so `/persist/keys/sops/secrets.yaml` (`0600 root:root`) stays in sync with the
repo copy. Do not edit `/persist/keys/sops/secrets.yaml` directly.

## Distributed Builds Key

The build mesh uses each host's own SSH host key as its `nix-builder`
client identity. There is no shared builder keypair and no SOPS file for it.

- Private side: `nix-daemon` reads `/persist/keys/ssh/ssh_host_ed25519_key`
  (already root-only) when connecting to remote builders.
- Public side: the `nix-builder` user on each builder authorizes every enabled
  client's host key. `keys.hosts.<name>.sshPublicKey` is derived from
  `machines.<name>.host.ssh` in `secrets/keys.nix`.

Rotation is the same as rotating that host's SSH host key. Adding a new host to
the build mesh just means registering its public key in `secrets/keys.nix`.

## Mesh Recipients And The `ai` Account

SOPS recipients are **host-only**: the encrypted blob is created for the 4 host
age recipients (one `.sops.yaml` creation rule, regenerated by `setup-sops.sh`
from `secrets/keys.nix`). Any host's root key can decrypt `secrets/secrets.yaml`,
while unprivileged users (`yi`, `ai`, `workd`) cannot. This is accepted for the
4-machine mutual-trust mesh; per-host isolation is a possible future change.

The read-only `ai` account (see [ai-ssh](ai-ssh.md)) has one key per machine,
but authorization is declared by each machine's `allow.ai` list. Currently only
yifuwuqi's AI key is accepted by the mesh. AI keys are **not** SOPS age
recipients. Generate them with `setup-sops.sh` and paste the printed machine
block into `secrets/keys.nix`.

## CI/CD Deployment Key (`keys/deploy`)

The Forgejo runner on `yifuwuqi` (`nix-builder`) receives a dedicated ed25519
private key delivered via SOPS to `/var/lib/nix-builder/.ssh/id_ed25519`
(`0400 nix-builder:nogroup`).

- **Purpose**: Enables `deploy-rs` running inside Forgejo CI to activate remote
  mesh nodes and self-deploy.
- **Authorization**: The matching public key (`keys.ci.deployPublicKey` in
  `secrets/keys.nix`) is authorized in `users.users.root.openssh.authorizedKeys.keys`
  across the gang.
- **Non-recipient**: The CI key is **not** an age recipient in `.sops.yaml` /
  `sopsAgeRecipients`. CI has permission to deploy configurations, but cannot decrypt
  SOPS secrets or access host age keys.
- **Operator Lane**: Remains root-only (`su -` then `deploy`) using
  `/persist/keys/ssh/ssh_host_ed25519_key`. `nix/deploy.nix` passes both `-i` flags
  so both operator and CI lanes work without manual reconfiguration.

### Key Generation and Rotation

To mint a new key or rotate an existing one (as root via `su -`):

```bash
# 1. Generate a new key in tmpfs on any configured host
./users/scripts/setup-sops.sh [--rotate]

# 2. Update secrets/keys.nix with the printed `ci = { deployPublicKey = "..."; };` snippet.

# 3. Ingest private key into SOPS
sops set secrets/secrets.yaml '["keys"]["deploy"]' "$(jq -Rs . < /run/ci-deploy-key/keys/deploy_ed25519)"
shred -u /run/ci-deploy-key/keys/deploy_ed25519
rm -rf /run/ci-deploy-key

# 4. Sync secrets to /persist/keys/sops/secrets.yaml and deploy/switch
./users/scripts/setup-sops.sh
```

## Search (yifuwuqi)

`search.fufu.land` -> SearXNG (`modules/services/searxng.nix`). It does not use

## Verification Checklist

Before rebooting or rolling out to another host:

- `/persist/keys/ssh/ssh_host_ed25519_key` exists and is `0600 root:root`.
- `ssh-keygen -y -f /persist/keys/ssh/ssh_host_ed25519_key` matches the host
  public key in `secrets/keys.nix`.
- `ssh-to-age -i /persist/keys/ssh/ssh_host_ed25519_key.pub` matches the host
  age recipient in `secrets/keys.nix` and `.sops.yaml`.
- `/persist/keys/sops/secrets.yaml` exists (`0600 root:root`) on hosts that need it.
- `/home/yi/.config/sops/age/keys.txt` does **not** exist (`setup-sops.sh` deletes it).
- `~/.ssh/id_ed25519` has no passphrase (`ssh-keygen -y -P "" -f ~/.ssh/id_ed25519`).
- `nixos-rebuild dry-activate --flake .#<host>` or an equivalent evaluation
  succeeds.
- SSH host fingerprints are expected after switching.
- SOPS secrets install successfully during activation.

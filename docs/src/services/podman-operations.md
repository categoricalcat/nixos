# Podman Operations

This runbook targets the rootful Podman services generated by
`virtualisation.oci-containers`. Use the rootful socket explicitly when
running read-only commands as a member of the `podman` group:

```console
$ podman --url unix:///run/podman/podman.sock ps --all
$ podman --url unix:///run/podman/podman.sock stats --all --no-stream
```

## Resource triage

Container CPU, memory, network, block I/O, and PID counts:

```console
$ podman --url unix:///run/podman/podman.sock stats --all --no-stream
```

Current and peak memory, cumulative CPU, and systemd IP accounting for a
container unit:

```console
$ systemctl show podman-firecrawl.service \
    -p ActiveState -p SubState -p NRestarts \
    -p CPUUsageNSec -p MemoryCurrent -p MemoryPeak \
    -p IPIngressBytes -p IPEgressBytes
```

Recent failures:

```console
$ journalctl -u podman-firecrawl.service --since today --no-pager
```

Grafana's **Workloads** dashboard is the historical view. It attributes
network traffic per container and per systemd unit, not to arbitrary
individual PIDs.

## Recover inconsistent storage

The failure below means Podman's overlay metadata references a missing link:

```text
creating read-only layer ...: readlink /var/lib/containers/storage/overlay/l/...: no such file or directory
```

An OCI service using `Restart=on-failure` can repeatedly pull the same image
after this error. Open a root login shell; all `#` commands below run in that
root account:

```console
$ su -
# systemctl stop podman-firecrawl.service
# systemctl is-active podman-firecrawl.service
inactive
```

Inspect the rootful store's metadata without rehashing every layer file:

```console
# podman system check --quick
```

Review the report, then remove damaged images and stale pull layers that are
at least one hour old:

```console
# podman system check --quick --repair --max=1h
# podman system check --quick
```

Do not add `--force` by default. It permits removal of containers that depend
on a damaged image. If the report says an in-use image blocks repair, identify
and stop only the named dependent container before deciding whether
`--force` is safe.

A full check verifies every extracted file. Nix-generated local images can
produce very large `layer content modified` reports there; those findings do
not establish the missing-link corruption addressed by this procedure.

Pull the image once, outside the service restart loop:

```console
# podman pull ghcr.io/firecrawl/firecrawl:latest
```

Reset the unit's start-limit counter and start it:

```console
# systemctl reset-failed podman-firecrawl.service
# systemctl start podman-firecrawl.service
# systemctl status podman-firecrawl.service --no-pager
# podman ps \
    --filter name=firecrawl --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}'
# curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:24002/
```

An HTTP status other than `000` confirms that the published port answered;
the root path need not return `200`.

> [!CAUTION]
> `podman system reset` removes every rootful container, image, network,
> volume, and the complete graph/run storage roots. It is not a routine repair
> command.

## Restart-loop guard

`podman-firecrawl.service` allows at most three starts per hour and waits five
minutes before an automatic retry. After the limit is reached, diagnose and
repair the cause, then explicitly clear the counter with
`systemctl reset-failed`.
